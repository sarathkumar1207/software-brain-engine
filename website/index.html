Why It Exists

LLMs should not read the whole repo for every focused change.

A change like replacing JWT authentication with Passport often touches predictable layers: auth strategy, middleware, controllers, DTOs, database entities, and tests. SBE builds a local index first, then asks the code graph what is likely affected before an AI agent spends tokens reading files.

Without SBE

The agent searches broad folders, opens unrelated files, and spends context before it understands the subsystem.

With SBE

The agent receives matched symbols, impacted files, dependency direction, layer classification, and token estimates.

Production Alpha Scope

Reliable local CLI behavior, binary storage, clear terminal output, repeatable validation, and transparent benchmark evidence.

Benchmark Proof

Measure token optimization before claiming it.

SBE compares full-project TypeScript source tokens against focused impacted symbol ranges plus metadata. It reports both wins and misses, because small projects can cost more metadata than they save.

Current estimator: Approximate tokens are calculated from source characters. Exact tokenizer support is planned after the validation harness is stable.

Install

Install like a normal developer tool.

SBE should feel closer to Git than a project folder. End users download one release artifact, install it, and run `sbe` from any terminal.

Windows

Download the MSI from GitHub Releases. It installs `sbe.exe` and updates PATH.

sbe-0.2.0-windows-x64.msi

macOS

Download the native archive and place the binary on PATH.

sbe-macos-arm64.tar.gz

Linux

Download the native archive or build from source while contributing.

sbe-linux-x64.tar.gz
CLI

Human-readable by default. JSON when tools need it.

sbe scan C:\repo Build or refresh the local `.sbe/` index.
sbe doctor C:\repo Check storage version, stale files, warnings, and index health.
sbe analyze-change "jwt to passport" C:\repo Return affected symbols, files, layers, and token estimates.
sbe benchmark C:\repo --query "jwt to passport" Compare full-repo context with focused SBE context.
sbe validate C:\repo --query "jwt to passport" Run scan plus benchmark and write `.sbe/reports/validation-latest.json`.
sbe export-json C:\repo Export the binary index to readable debug JSON.
Architecture

Modular Rust workspace built for growth.

Each crate owns one responsibility so the project can scale without becoming one large CLI file.

scannerwalks repos, ignores generated folders, hashes source files
parserextracts TypeScript symbols, imports, nesting, references
storageowns `.sbe/` binary snapshots, manifests, debug export
graphbuilds directed relationships for imports and references
impacttraverses reverse dependencies for affected symbols
queryproduces inspect, benchmark, and change-analysis reports
indexerruns scan, parse, storage, and warnings end to end
cliturns engine reports into terminal and JSON output
Validation

Prove it on real projects, then improve the misses.

The validation script builds the release binary, scans a project, runs a benchmark query, and stores a report under `.sbe/reports/`. That gives contributors a repeatable way to compare correctness and token behavior.

Windows

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-benchmark.ps1 -ProjectPath C:\repo -Query "jwt to passport"

macOS and Linux

scripts/validate-benchmark.sh /path/to/repo "jwt to passport"
Open Source Release Model

Source code stays clean. Releases ship only usable artifacts.

`target/`, `dist/`, `.sbe/`, WiX intermediates, and generated reports are local output. GitHub Releases should expose the MSI and platform archives, not build folders.

  1. 1 Push source to `main`
  2. 2 CI runs fmt, tests, clippy, release build
  3. 3 Version tags publish downloadable artifacts
  4. 4 Website publishes from `website/` to `gh-pages`
